Ammplify: AuditForge alongside solidity-auditor v4

Pashov Audit Group benchmarked its open-source solidity-auditor v4 on the judged Sherlock contest for Ammplify. We ran AuditForge on the same code and scored it against the same 36 judged issues, using the same three-run format.

AuditForge is a multi-agent audit pipeline built for pre-audits and audit support. For every High/Medium it ships, it writes and executes a Foundry PoC against the real contracts, so each finding arrives with proof. That depth takes time, and run time grows with the size of the codebase.

4 · The triage trade-off

Where the line is drawn between "report it" and "close it" trades triage effort against coverage. We measured both ends on this contest, counting distinct root causes.

Fully automated report 53.2%

of reported root causes match a judged issue (25 of 47).

  • Fewer items for a human to triage.
  • Higher precision.
  • Some issues the agents found are lost: automated gates closed or cut 4 judged issues before the report.
AI detection ~27–38%

of raised root causes match a judged issue (29 of an estimated 77–109).

  • More items for a human to triage.
  • Lower precision.
  • More issues found: 30 of 36 judged issues were raised at the right code.

The detection-basis denominator is a range because closed candidates are logged as ledger rows rather than titled findings; grouping them by root cause gives between 30 and 62 additional candidates. We are working on keeping the detection-level coverage while holding the report's precision, by re-attacking rule-based closures with a separate agent instead of reopening all of them.

How this was measured

TargetSherlock contest 1054 (Ammplify), audited commit 1efcfd57, 24 files, 2,949 nSLOC
Answer key36 judged issues: 13 High, 23 Medium (the same set Pashov Audit Group scored against)
MatchingSame root cause (same mechanism at the same code), each judged issue counted once
Runs3 runs; each later run received the earlier runs' findings (titles and locations only) to look elsewhere, mirroring v4's loop mode
BlindnessAll three runs were frozen and committed before the judging results were opened; predictions were registered before the first run
v4 numbersTaken from Pashov Audit Group's published write-up, which reports the union of three runs; not re-run by us
CaveatThe contest predates both tools' model knowledge cutoff, so neither result is a fully out-of-sample number. One target is a small sample.

AuditForge findings that match no judged issue are not published here. Some may be real, unreported issues and are handled through responsible disclosure.
