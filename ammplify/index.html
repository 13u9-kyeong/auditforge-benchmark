Reading these numbers

Two tools built for different jobs: solidity-auditor is a fast review skill; AuditForge is a multi-agent pipeline that executes a proof-of-concept test for every finding it submits. The figures are shown side by side, not as a ranking.

  • The v4 figures come from Pashov Audit Group's published write-up (union of three runs). We did not run v4, and the write-up does not state the model or settings used.
  • The medium-effort run also used a newer AuditForge version (1.2.2), so effort and version are not separated.
  • One three-run loop per configuration on one target; run-to-run variance is not measured. Parts of AuditForge 1.2.2 were developed on this contest, so its result is in-sample.
  • The contest predates the knowledge cutoff of the model AuditForge ran on, so neither AuditForge result is fully out-of-sample.

How this was measured

TargetSherlock contest 1054 (Ammplify), audited commit 1efcfd57, 24 files, 2,949 nSLOC
Answer key36 judged issues: 13 High, 23 Medium (the set Pashov Audit Group scored against)
MatchingSame root cause (same mechanism at the same code); each judged issue counted once
Runs3 runs per AuditForge configuration; each later run received the earlier runs' findings (titles and locations only) to look elsewhere. Figures are the union of the three runs
BlindnessEvery AuditForge run was frozen and committed before the judging results were opened; predictions were registered before the first run
v4 numbersTaken from Pashov Audit Group's published blog write-up; not re-run by us; model and settings not stated in the source

AuditForge findings that match no judged issue are not published here. Some may be real, unreported issues and are handled through responsible disclosure.
